# 115 Search Pro

> **115 网盘番号资料库助手** —— 把散落在网盘里的番号视频收录成本地资料库，
> 自动提取番号、联网补齐影片信息，然后**按演员 / 类别搜索筛选、一键播放**。

一个 Tampermonkey 用户脚本。**零依赖、零 API key、零服务端** ——
所有请求在你的浏览器里发出，数据全部存在本机 IndexedDB，**不会修改 115 上任何文件**。

```
收录目录  →  识别番号  →  补齐演员/类别  →  搜索筛选  →  一键播放
   📥          🔍            🌐             🔎          ▶
```

## 它解决什么问题

115 网盘里的视频文件名往往是一串番号，**除了数字字母什么都看不出来**：

```
hmpd-10044.mp4
SONE-119[中文字幕].mkv
[高清] DVAJ-556 无码破解.mp4
```

想找「某位演员的作品」或者「某个类别的片子」，只能靠记忆和一个个点开看。
网盘自己的搜索也帮不上忙 —— 它只能搜文件名。

本脚本做的事情：

1. **收录**：读取目录下所有视频文件名
2. **识别**：从文件名里提取番号（`hmpd-10044.mp4` → `HMPD-10044`）
3. **补齐**：用番号去公开影片库查询标题、演员、类别
4. **建库**：把这些信息存进浏览器本地资料库
5. **检索**：按演员、类别、关键词搜索筛选，点一下直接播放

## 核心功能

### 📥 一键收录整个目录（不受网页分页限制）

点一下「收录本目录」，脚本调用 115 官方接口拉取**该目录的完整清单** ——
不是只抓当前屏幕上那 24 条。

| | 网页版列表 | 本脚本收录 |
|---|---|---|
| 单次可见 | 24 条 / 页 | **全量**（自动翻页，1000 条/次） |
| 78 页的目录 | 要手动翻 78 次 | 一次点完 |
| 附带信息 | 只有文件名 | 文件名 + `pickcode` + 文件大小 + 目录内位置 |

接口不可用时（未登录 / 改版 / 限流）会**自动回退**到 DOM 扫描，并在提示里说明
「这种方式只能收当前页」，不会假装成功。

### 🔄 增量更新（目录里不断加新视频）

**再点一次「收录本目录」就行。** 收录天然是增量的，不会重复抓：

| 分类 | 判定 | 行为 |
|---|---|---|
| **新增** | 库里没有这个文件 | 查数据源 |
| **待补** | 库里有，但上次没拿到标签 | 只重查这些番号 |
| **未变** | 库里有、标签完好、番号没变 | **零请求**，只刷新文件信息 |
| **失效** | 库里有，这次目录里没有了 | 打标记（不删，万一是临时移动） |

完成后提示 `✅ 新增 N · 补查 M · 未变 K · ⚠️ 失效 W`，每个分类的含义都会写在提示区。

**进到以前收录过的目录时，面板还会主动提示「本目录上次收录于 X 天前（N 个视频）」**，
提醒你可以直接增量更新。

> 想完全重来一遍（比如怀疑数据源抽风），点旁边的 **🔄 全量重抓**。

### 🔎 资料库：按演员 / 类别精确筛选

资料库页签里有：

| 区域 | 作用 |
|---|---|
| 搜索框 | 关键词模糊匹配 **番号 / 标题 / 文件名 / 演员 / 类别** |
| 演员 / 类别 下拉 | **多选框**，每项带出现次数；有搜索框可过滤；支持全选/清空 |
| 结果列表 | 每行显示 番号 · 标题 · 演员 · 类别，右侧「▶ 播放」「移除」 |

**筛选语义**：同一维度内多选是 **AND**
—— 勾「演员A」+「演员B」= 同时有这两个人的作品；再叠加类别就是三重条件。

数量显示有两处：
- 筛选区下方一行实时显示 `共 N 条 · 命中 M · 标签 K · 译好 X / 半译 Y`（鼠标悬停看完整说法）
- 每个下拉选项后面跟着它自己的出现次数（如 `演员A 12`）

#### 结果列表是**滚动加载**的

命中很多条时不会一次性全塞进页面（那样会卡），而是**分批渲染**：

| | 行为 |
|---|---|
| 初始 | 先渲染 **50 条** |
| 滚动 | 滑到底部**自动加载下 50 条**，不用点任何按钮 |
| 底部提示 | 常显「已显示 50 / 共 3869 条 · 继续下滑自动加载」 |
| 加载完 | 明确改写为「**已全部显示（共 43 条）**」 |

> 最后那句是刻意加的：滚到底却没等到新内容时，人很容易怀疑「是不是还有没加载出来的」。
> 明说「已全部显示」才能打消这个疑虑 —— 这比加一个翻页控件更解决问题。
>
> 列表区会**自动吃满面板剩余高度**，滚动只发生在列表内部，顶部的搜索框和筛选条件始终可见。
> 万一浏览器不支持自动加载，底部会出现「加载更多」按钮兜底。

#### 为了让列表尽量高，筛选区被压到两行

面板宽度固定 380px、高度 80vh，**筛选区每让出 1px，列表就多 1px**。所以：

| | 改前 | 改后 |
|---|---|---|
| 固定开销 | 368px | 261px |
| 列表可用高度 | 298px | 459px |
| 约合可见条目 | 3.3 条 | 5.0 条 |

具体动了四处：

1. **演员 / 类别 并排一行**（原来是各占一行的竖排，白吃 84px）
2. **统计行钉成单行**，并在超长时用省略号截断（原来文案长到必然折两行）
3. **底部四个按钮文案压短**，从两行变一行（`翻译标题`→`翻译`，`清理失效条目`→`清理失效`，详细说明移到悬停提示）
4. **抽屉高度 74vh → 80vh**

改前的固定开销里，光是「统计行折两行」和「按钮行折两行」就白吃掉了 86px。

### ▶ 一键播放

| 播放方式 | 行为 |
|---|---|
| **直接打开播放页**（默认） | 用 `pick_code` 拼出播放地址，新标签页一步直达 |
| **回到目录、页面内打开** | 跳回文件所在目录第 N 页 → 定位高亮 → 自动点开（**不依赖任何插件**） |

默认走播放页，**一步直达、不用翻页找**。地址模板可在设置里改，
支持 `{pickcode}` `{cid}` `{fileId}` 变量。

脚本还带**播放页自检**：打开后如果页面是白的（多半是没装对应插件），
会直接浮出说明卡片告诉你原因和两条出路，**不会让你对着白屏发懵**。

### 🈶 中文标题（纯本地翻译，不联网）

日文片名自动译成中文，**列表里只显示一行中文，鼠标悬停看原文**。
想常驻对照的，设置里可切成「中文一行 + 原文一行」。

译文角标分两种：`译` = 基本能读；`半` = 只译到一部分（悬停能看到具体覆盖率）。

为什么是「本地术语表」而不是调翻译接口：

| | 本地术语表 | 联网翻译 |
|---|---|---|
| 成本 / 配额 | 0，无限制 | 有额度，几千条是一笔钱 |
| 速度 | 即时（纯字符串替换） | 每条一次请求 |
| 稳定性 | 不会失效 | 接口挂了就没译文 |
| 质量 | **看得懂词，但不成句** | 更通顺 |
| 内容审核 | 不存在这个问题 | 成人向标题常被拒答或「净化」 |

> ⚠️ **先说清这条路的天花板**，免得期望落空。
>
> 术语表是「**词对词替换**」。它能把 `同窓会` 换成 `同窗会`、`専属決定` 换成 `专属决定`，
> 但翻不掉**语法**。真实片名大多是完整句子，剩下的部分是动词活用和助词
> （`酔った` `抱かれた` `教えてくれる` `い` `が` `った` …），
> **这些不是词，词典再大也补不上**。
>
> 所以本地路线的产出必然是「一半中文一半日文」。它的定位是
> **帮你认出这部片讲什么**（关键词可读），不是给你一个通顺的译名。
> 想真正通顺，只有联网机翻一条路 —— 但那要接受上面那张表里的代价。

两道保障质量的关键机制：

1. **专名先占位、翻完再回填** —— 番号和演员名绝不参与翻译。
   省掉这步，演员名会被逐字替换成一串毫无意义的汉字。
2. **字形归一化** —— 术语表只能收整词，剩下的汉字会原样流下来，
   而它们是日文写法。所以回填之前要过一遍字形表：

   | 原文 | 不做归一化 | 做了归一化 |
   |---|---|---|
   | `夫婦交換` | 夫婦交換 | 夫妻交换 |
   | `家庭教師の誘惑` | 家庭教師の誘惑 | 家教的诱惑 |
   | `専属決定` | 専属決定 | 专属决定 |

**译得不全怎么办？** 用数字说话，不假装翻好了。面板顶部按覆盖率分三档报数
（**译得动 / 半译 / 完全没译**），而不是含糊的「已译 N 条」。

想提高覆盖率就先看缺口在哪：

```bash
node tools/glossary-gaps.mjs 资料库备份.json     # 面板「导出资料库」的文件
```

它会按**出现次数**列出没译到的词，并把「可补的词」和「补不了的语法碎片」分开报 ——
碎片占多数就说明天花板到了，该考虑联网方案而不是继续堆词典。

补词方法：编辑 `src/core/glossary.js` 的词条表 → `GLOSSARY_VERSION` 加一 → 重新构建。
**已译条目会自动重译**（缓存哈希里含词典版本），不用手动清缓存。
不开浏览器直接看效果：`node tools/preview-translate.mjs "标题"`。

### 🌐 三个数据源 + 自动降级

| 数据源 | 内容 | 需要 key |
|---|---|---|
| **JavBus** | 标题、演员、类别、发行日期 | 不需要 |
| **javlibrary** | 标题、演员、类别、评分 | 不需要 |
| **DMM** | 最结构化（含封面、简介） | 可选申请 |

优先级 JavBus → javlibrary → DMM，前一个失败自动降级到下一个，
结果写入本地缓存（可设过期时间），重复收录不再请求。

### 🛠 排障工具链

收录/播放不生效时，面板自带一排诊断按钮：**诊断问题**、**复制诊断摘要**（一键复制纯文本）、
**DOM 采样**、**建库/播放入口探针**、**采样视频行结构**。另有 15+ 个控制台命令
（`__jv115.diagnose()` 等），详见 [技术文档](docs/TECHNICAL.md#八调试)。

### 💾 数据导出 / 导入

标准 JSON 格式备份，可跨设备迁移。既有「完整备份」（含缓存），
也能单独「导出资料库」（只导出收录结果，便于外部分析）。

## 功能详解

### 扫描页

| 按钮 | 作用 |
|---|---|
| `📥 收录本目录到资料库` | **主流程入口**，增量收录（走 115 接口拿全量） |
| `🔄 全量重抓` | 忽略已有记录，本目录所有番号重新查一遍 |
| `扫描并打标签` | 只抓元数据进本地缓存，不上屏（预抓取 / 排障用） |
| `强制刷新(忽略缓存)` | 忽略缓存重新抓取 |
| `清除本页标签` | 清除历史版本残留在页面上的旧标记 |
| 🔍 / 📋 / 🧬 / 🔬 / 🎬 | 一组排障工具，见 [技术文档](docs/TECHNICAL.md#八调试) |

### 资料库页

搜索框、演员/类别多选筛选、结果列表（**每批 50 条滚动加载**）、播放、移除、
`🌐 翻译标题`、`导出资料库`、`🗑 清理失效条目`。

列表每条的标题默认**只有一行中文，鼠标悬停看原文**。术语表译出来的会挂角标：
`译` = 基本能读、`半` = 只译到一部分（悬停能看到覆盖率）。
没有译文时老实显示原文，**不会留空白**。

失效条目默认不参与搜索筛选。文件确实删了，点「清理失效条目」清掉即可。

### 设置页

- **数据源开关**（JavBus / javlibrary / DMM 各自独立开关）
- **域名自定义**（支持镜像站）
- **并发数**（收录时同时查多少个番号）
- **最低置信度**（过滤掉识别不确定的结果）
- **演员 / 类别显示数**（`0` = 全部显示）
- **播放方式**（直接打开播放页 / 回到目录页面内打开）
- **播放地址模板**（含 `{pickcode}` `{cid}` `{fileId}` 变量）
- **标题中译**：显示方式（只中文+悬停原文 / 中文一行+原文一行 / 只原文）、查询后自动翻译、
  `🔄 用当前词典全部重译`；旁边标着当前词典版本和词条数
- **测试数据源连通性** —— 一键检测各源是否可用

### 数据页

元数据条目 / 资料库条目 / 收录目录 三项统计、导出/导入备份、清理过期缓存。

## 番号识别能力

内置 200+ 常见厂商前缀，带置信度评分：

```
SSNI-730.mp4                → SSNI-730    (99)
ABP_456 中文字幕.mp4         → ABP-456     (99)
MIAA123.mp4                 → MIAA-123    (98)
abc-123-c.mp4               → ABC-123     (75)
h_123.mp4                   → H-123       (85)
[高清] DVAJ-556 无码破解.mp4  → DVAJ-556    (99)
SONE-119[中文字幕].mkv        → SONE-119    (99)
120123-456-1pon.mp4         → 120123-456  (75)
```

**不会误判**：`1080P.mp4` / `4K_HD.mkv` / `x264-1080.mkv` / `EP01.mp4` / `S01E05.mp4`
→ 全部返回 `null`（这些都是分辨率、编码和剧集标记，不是番号）。

识别不确定的可以用「最低置信度」过滤。文件名里确实没有番号的
（比如「第01集.mp4」）会正常入库，只是标为「未获取到标签」。

## 数据安全与备份

- 数据存在浏览器 **IndexedDB**（库名 `jv115-tagger`）
- **不修改 115 上任何文件**，纯读取
- 所有网络请求**从你的浏览器直接发出**，不经过任何中间服务器
- **换浏览器 / 清缓存会丢失数据** → 请定期在「数据」页导出备份
- 备份是标准 JSON，可跨设备导入

## 常见问题

**Q：收录时提示「抓取被拦截」？**

JavBus / javlibrary 有 Cloudflare 防护。**手动在浏览器新标签页打开一次 javbus.com**，
通过验证后回到 115 页面再收一次即可。脚本会自动检测拦截并给出提示。

**Q：收录完提示「只能收当前页」？**

说明 115 接口那条路失败了（未登录 / 接口改版 / 被限流），脚本降级到了 DOM 扫描。
DOM 扫描受网页分页限制，一次只能收当前页。**重新登录 115 或稍后重试**通常能恢复。

**Q：点播放跳到了目录，但没找到视频？**

两种情况，提示会分别说明：
- **旧记录没记文件位置**（早期版本收录的）→ 重新收录一次该目录即可精确定位；
- **翻到目标页还没找到** → 115 网页排序和接口排序可能不一致，建议改用「直接打开播放页」。

**Q：点播放打开了白屏？**

默认播放地址是 115Master 脚本注册的路由，**没装 115Master 就是空白页**。
脚本会自检并弹说明卡片。二选一：
- 装 [115Master](https://github.com/zhuzi6/115master)（一步直达 + 字幕等增强）
- 到「设置 → 播放方式」改成「回到目录、页面内打开」

**Q：列表里有条目带 `缺提取码` 角标？**

旧版本收录的记录可能没有 `pickcode`（播放地址的必填参数）。
进那个目录点一次「📥 收录本目录」就能补全 —— 增量收录只补这一条，很快。

**Q：能全盘自动扫描吗？**

没有做，也不打算做 —— 全盘递归极易触发风控，号被限反而更麻烦。
逐个目录手动收录最稳，而且单个目录是**全量**的。

**Q：手机上能用吗？**

不能，需要浏览器 + Tampermonkey。数据也只在装了脚本的浏览器里可见，115 App 看不到。

## 已知限制

| 限制 | 说明 |
|---|---|
| 只读展示 | 数据只在装了脚本的浏览器可见，115 App 看不到 |
| 依赖站点可用性 | javbus / javlibrary 需能从你的网络访问 |
| Cloudflare | 可能需手动过一次验证 |
| 番号覆盖率 | 文件名里没有番号的（如「第01集.mp4」）无法识别 |
| 收录是手动逐目录的 | 没有全盘递归（易触发风控）；但单目录是全量的，重复点即增量更新 |
| 收录依赖 115 官方接口 | 接口改版/限流时降级到 DOM 扫描（**只能收当前页**），提示里会说明 |
| 页面内播放非 100% | 靠模拟鼠标事件触发 115 自己的播放器；115 改结构时可能失效，可用诊断工具回报 |
| 翻页定位依赖接口排序 | 用收录时记下的位置算页码；若 115 排序变了可能落错页，失败会给明确提示，不会静默 |
| 失效判定是启发式 | 「上次收录过、这次目录里没有」即标失效；文件移回后下次收录会自动恢复 |
| 播放页需插件 | 默认地址是 115Master 注册的，没装它就是白屏；脚本会告知，也可切「页面内打开」 |
| 超大库 | 筛选是内存过滤 + **分批渲染**（每批 50 条，滚到底自动加载）；几万级仍可能偏慢，届时需改用索引游标 |
| 115 改版 | 列表 DOM 结构若变动，选择器可能需要调整 |
| 中文标题是**机器译名** | 本地术语表逐词替换，不是人工翻译，也**不是官方译名**。长句不成句，词典没收的词会留日文原样 —— 这是「词对词替换」的固有天花板，悬停可随时看到原文 |
| 术语表需要长期补词 | 片假名外来语无法逐字转换，必须整词收录。用 `node tools/glossary-gaps.mjs` 看缺哪些（按出现次数排序），按需补即可 |

## 版本与回退

每个版本都打了 git tag，历史版本的 `dist` 产物一直留在仓库里。
完整改动记录和三种回退方式见 **[CHANGELOG.md](CHANGELOG.md#如何回退)**。

最常用的一种 —— 装回某个历史版本（把 tag 换掉即可）：

```
https://github.com/q5210823/115searchpro/raw/v1.3.1/dist/jv115-tagger.user.js
```

> 重装旧版后 Tampermonkey 会自动升级回去（脚本头有 `@updateURL`）。
> 想稳定留在旧版，到 Tampermonkey 管理面板关掉该脚本的「自动更新」。

**数据是向后兼容的**：新版本只往记录里加字段，没动主键和表结构。
用旧版脚本读新版写的数据不会出错，代价只是旧版里看不到中文译文 ——
换回新版立刻就有，而且不用重算。

## 开发

```
src/main.js              主入口（角色判定 + 编排 + 收录 + 播放/定位）
src/core/
  frames.js              跨 frame 通信（角色判定 / postMessage）
  tag-extractor.js       番号提取（正则 + 置信度）
  providers.js           数据源（JavBus / javlibrary / DMM）+ 降级
  storage.js             IndexedDB 本地库（5 张表）
  paging.js              资料库列表分批渲染的纯计算
  glossary.js            标题中译（术语表 + 字形表 + 专名保护，纯函数）
  ui.js                  Shadow DOM 样式 + Toast
  site-115.js            115 页面适配（扫描 / 接口 / 播放触发 / 诊断）
  panel.js               控制面板（扫描 / 资料库 / 设置 / 数据）
build.mjs                打包成单文件 UserScript（手写 bundler，零依赖）
docs/TECHNICAL.md        技术实现细节 + 踩坑记录 + 排障手册
tools/glossary-gaps.mjs      统计缺哪些词（按出现次数排序，补词典用）
tools/preview-translate.mjs  命令行看翻译效果（补词条时用）
tests/                   15 个测试文件（`node tests/run_all.mjs` 一把跑完）
CHANGELOG.md             版本改动记录 + 回退指南
```

**补词条 / 改翻译规则**

```bash
node tools/glossary-gaps.mjs 备份.json      # 先看缺口在哪、哪些词最值得补
node tools/preview-translate.mjs            # 看内置样例
node tools/preview-translate.mjs "日文标题"  # 看指定标题
```

编辑 `src/core/glossary.js` → 把 `GLOSSARY_VERSION` 加一 → `node build.mjs`。
已译条目会自动重译，不需要手动清缓存。

**构建**

```bash
node build.mjs
```

**测试**

```bash
node tests/run_all.mjs
```

> 判据是**进程退出码**，不是「输出里有没有 ❌」。有过一次教训：某个测试文件加载期
> 直接崩溃，不打印任何 ❌，被误判成「通过」，连续两个版本号都没发现。

想了解内部机制、踩过的坑、怎么排障 → 看 **[docs/TECHNICAL.md](docs/TECHNICAL.md)**。
